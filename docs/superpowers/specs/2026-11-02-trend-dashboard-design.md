# 개발 트렌드 대시보드 설계

작성일: 2026-11-02
참고: https://github.com/jihoo12/trends (원본보다 단순하게)
화면 시안: https://claude.ai/artifact/DZYr9r6bJLrzCt1GoNUKNp 의 "D. 풀 + HN, arXiv" 아트보드

## 1. 목적

매일 아침 한 페이지에서 개발 트렌드를 확인한다. 핵심은 "이번 주 GitHub에서 별을 가장 많이 받은 레포"이고,
Hacker News 인기 글, arXiv 최신 논문, 세 소스를 합친 키워드 트렌드를 함께 보여준다.
폰/PC 어디서나 열 수 있어야 한다.

## 2. 목표 / 비목표 / 안티 목표

목표
- 이번 주 별 증가 상위 레포 순위와 어제 대비 순위 변동
- 상위 5개 레포의 14일 별 증가 추이 그래프, 행별 미니 추이선
- 새로 진입한 레포 / 순위에서 빠진 레포
- 키워드 트렌드 (오늘 vs 7일 평균)
- HN 오늘의 인기 글, arXiv 최신 논문 목록
- 매일 자동 수집·배포, 비용 0

비목표 (원본에 있지만 뺌)
- 영어/한국어 전환 (한국어만)
- 기간/언어 필터 버튼 (시안 C의 버튼은 D에서 섹션 이동 링크로 대체됨)
- 서버, DB, 로그인

안티 목표
- 소스 하나가 깨졌다고 페이지 전체가 비거나 배포가 멈추는 것
- 외부 패키지 설치가 필요해지는 것 (Python 표준 라이브러리만)

## 3. 사용자가 정한 것

- 화면: 시안 D (긴 한 페이지, 위→아래: 요약 카드 4개 / 레포 그래프·진입·이탈 / 레포 표 / 뜨는 키워드 / HN·arXiv 2단, 상단 섹션 이동 링크)
- 언어: Python (표준 라이브러리만)
- 자동화/호스팅: GitHub Actions 매일 실행 + GitHub Pages. 사용자의 GitHub 계정 사용.
- 레포는 공개(public). 무료 플랜 Pages 조건. 페이지와 data/ 가 공개되는 것에 동의함.
  Actions 권한: `contents: write` (data/ 커밋), `pages: write` + `id-token: write` (Pages 배포).

## 4. 구성

```
collect.py          # 세 소스 수집 → data/YYYY-MM-DD.json 저장
build.py            # 최근 90일 스냅샷 → site/history.json (화면용 사전 계산)
site/index.html     # 페이지 1장 + 순수 JS, history.json을 fetch해서 렌더
tests/              # unittest + 저장해둔 HTML/JSON 픽스처
.github/workflows/daily.yml
```

collect.py와 build.py를 하나로 합칠지는 빌더 판단.

### 4.1 데이터 소스

| 소스 | 방법 | 수집 내용 |
|------|------|-----------|
| GitHub Trending | `https://github.com/trending?since=weekly` HTML 파싱 (공식 API 없음) | 순위, owner/repo, 설명, 언어, 전체 별, "stars this week" (25개) |
| Hacker News | 공식 Firebase API `topstories` 상위 N개 + `item/{id}` | 제목, URL 도메인, 점수, 댓글 수, HN 링크 |
| arXiv | `export.arxiv.org/api/query` Atom XML, 제출일 최신순 | 제목, 저자(첫 저자 + 외 N명), 분야, 링크 |

### 4.2 계산

- "어제" = Trending 수집에 성공한 가장 최근 이전 스냅샷 (작성자 판단). 하루 실패해도 전부 NEW가 되지 않게.
  이전 성공 스냅샷이 아예 없으면(첫날) 변동 칸은 "–".
- 순위 변동: 오늘 순위 vs "어제" 순위. "어제"에 없던 레포는 NEW.
- 새로 진입 / 빠짐: "어제" 목록과 오늘 목록의 차집합.
- 7일 증가: GitHub이 주는 "stars this week" 값을 그대로 사용.
- 14일 추이 (작성자 판단): 대상은 오늘 "7일 증가" 상위 5개(그래프)와 표의 각 행(미니 추이선).
  값은 "14일 창 안에서 처음 기록된 전체 별 수 대비 누적 증가량" = 그날 전체 별 − 창 안 첫 기록 전체 별.
  그 레포가 Trending에 없던 날은 값 없음 → 선을 끊는다(보간하지 않음). 기록이 1일뿐이면 점 하나.

### 4.2.1 요약 카드 4개 (시안 D 기준)

1. 레포 1위 7일 증가: 값 `+4,812`, 보조 문구 레포 이름
2. 새로 진입 레포 수: 값 개수, 보조 문구 "어제 대비"
3. HN 최고 점수: 값 점수, 보조 문구 "오늘 인기 글 1위"
4. 가장 뜨는 키워드: 값 단어, 보조 문구 "7일 평균 대비 +N%" (7일치 미만이면 "데이터 쌓는 중")
- 키워드 트렌드: HN 제목 + 레포 설명 + arXiv 제목을 소문자 단어로 쪼개고 불용어 제거 후 빈도 집계.
  오늘 빈도 vs 직전 7일 평균의 증가율 상위 8개. 7일치 미만이면 "데이터 쌓는 중" 표시.

### 4.3 실패 처리

- 소스마다 try/except로 분리. 실패한 소스는 스냅샷에 `{"error": "..."}`로 기록하고 나머지는 저장.
- 페이지는 실패한 섹션에 그 소스의 마지막 성공 데이터를 보여주고, 위에 "오늘 수집 실패 · N일 전 데이터" 경고를 붙인다 (작성자 판단).
  성공 데이터가 한 번도 없으면 "수집 실패" 문구만. 나머지 섹션은 정상 표시.
- 세 소스 모두 실패해도 이전 데이터로 페이지는 유지된다.
- 같은 날 재실행 시 그날 파일 덮어씀.

### 4.4 자동화

- GitHub Actions cron 하루 1회 09:00 KST (`0 0 * * *` UTC), 수동 실행(`workflow_dispatch`) 가능.
- 순서: collect → data/ 커밋·푸시 → build → site/ 를 Pages에 배포.
- 90일 지난 스냅샷은 build가 읽지 않음 (파일 삭제는 하지 않음).
- 이 PC에서 08:30~08:40에 도는 다른 작업과는 무관 (GitHub 서버에서 실행).

### 4.5 화면

- 시안 D의 레이아웃·색·글꼴(Noto Sans KR, JetBrains Mono)을 따른다.
- 그래프는 라이브러리 없이 SVG로 직접 그린다.
- 폰 폭(약 390px)에서 2단 영역은 세로로 쌓이고 표는 가로 스크롤.
- 링크는 실제 GitHub / HN / arXiv 주소로 연결.

## 5. 빌더에게 맡긴 것 (작성자 판단으로 정한 기본값 포함)

- arXiv 분야: `cs.AI` 기본값 (작성자 판단). 설정 상수 하나로 바꿀 수 있게.
- HN 목록 개수 10, arXiv 10, Trending 25 (작성자 판단).
- 불용어 목록 내용, 단어 쪼개는 규칙.
- 파일 하나로 합칠지, HTML 파싱 방식(html.parser vs 정규식).
- 테스트: Trending 파서, 키워드 집계, 순위 변동 계산에 픽스처 기반 unittest.
